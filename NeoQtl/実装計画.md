# NeoUtlからNeoQtlへの全ロジック移植およびQML GUI完全刷新 実装計画

## 1. 概要と目標
本プロジェクトは、NeoUtl（eguiベースの動画編集ソフトウェア）の全ロジックをサブプロジェクト `NeoQtl` に移植し、GUIをeguiからQt Quick / QMLに完全に置き換えるものである。
既存のNeoUtlワークスペース（`crates/` や `src/` 等のNeoUtl本体ファイル）は一切変更せず、**`NeoQtl` 内部のファイルのみ**を編集・構築する。
また、QMLはJITではなく**AOT（Ahead-Of-Time）コンパイル**を行い、ソースコードがなくても単一バイナリに静的リンクされて動作するビルドフローを確立する。

---

## 2. アーキテクチャと変更スコープ

### 2.1 依存関係・ワークスペース設定 (`NeoQtl/Cargo.toml`)
- NeoUtl本体で使用されている全クレート（`neoutl-shared-abi`, `neoutl-object-api`, `neoutl-effect-api`, `neoutl-media-runtime`, `shipyard`, `rodio`, `wgpu`, `prost`, `rust-i18n` 等）を `NeoQtl/Cargo.toml` に追加。
- egui関連の依存（`egui`, `egui-wgpu`, `egui-winit`, `winit`, `egui_extras`, `egui-elegance` 等）を排除。
- `build-dependencies` に `neoutl-object-shader-build`、`cc`、`cxx-build`、`cxx-qt-build` を設定。

### 2.2 ビルドフローとQML AOT静的リンク (`NeoQtl/build.rs`)
Qt6標準の `qmlcachegen` および `rcc` を活用したAOTビルドフローを構築：
1. **リソースフィルタリング**:
   `qmlcachegen --filter-resource-file -o <filtered.qrc> <qml.qrc>`
   QMLファイルを除外したリソース定義を生成（生のQMLテキストをRCCバイナリから除外）。
2. **QML AOTコンパイル**:
   各 `.qml` ファイルに対して `qmlcachegen --resource=<qml.qrc> -o <qml_name_qml.cpp> <qml_file>` を実行し、バイトコード／C++ユニットを生成。
3. **ローダーコード生成**:
   `qmlcachegen --resource-file-mapping="<abs_qrc>=<filtered_qrc>" -o qmlcache_loader.cpp <abs_qrc>`
   QMLエンジンが `qrc:/...` を読み込む際にAOTコンパイル済みユニットを返す登録フックを生成。
4. **C++静的リンク**:
   生成された各 `_qml.cpp`、`qmlcache_loader.cpp`、および `wgpu_rhi_item.cpp` を C++ コンパイラでコンパイルし、静的リンク。
5. **Slangシェーダーのコンパイル**:
   `neoutl_object_shader_build::compile_object_shader` を呼び出し、メディア用シェーダー（`media.slang`, `media_video.slang`）をビルド時にWGSLへトランスパイル。
6. **テーマ・アセットのコピー**:
   `assets/themes` をビルド出力ディレクトリへコピー。

### 2.3 NeoUtlロジックの移植 (`NeoQtl/src/`)
以下のモジュール群をNeoUtlからコピーし、NeoQtl用に調整：
- `app_state.rs`: アプリケーション状態およびECSワールド管理
- `audio/`: Rodio音声再生、プラグインレジストリ、設定
- `config.rs`: 定数群
- `crash_report.rs`: Sentryクラッシュレポート（無効化設定対応）
- `document.rs`: プロジェクトファイル（.neoutl）の保存・復元
- `easings/`: イージングローダーおよび標準イージング
- `ecs/`: Shipyardによるエンティティ・コンポーネント・システム
- `effects/`: エフェクトローダー（Lua/Slang/Rust ABI）
- `export.rs`: ffmpeg連携エクスポートロジック
- `gpu_shared.rs`: wgpu初期化ロジック（`egui_wgpu::wgpu` から `wgpu` へ変更）
- `hot_reload.rs`: ホットリロード通知
- `localization.rs`: rust-i18nローカライゼーション初期化
- `objects/`: オブジェクトローダー（テキスト、図形、画像、動画等）
- `project.rs`: プロジェクトセッション、コマンド履歴（Undo/Redo）
- `renderer/`: wgpuレンダリングパイプライン（`use egui_wgpu::wgpu;` を `use wgpu;` に変更）
- `schema.rs`: プロトコルバッファシリアライズ
- `shortcuts.rs`: ショートカット定義・アクションマッピング
- `theme.rs`: カラーテーマ管理
- `update.rs`: バージョン更新確認
- `i18n/`, `assets/`: リソースファイルの配置

### 2.4 レンダラーとQt RHIゼロコピー連携 (`NeoQtl/src/renderer.rs`, `NeoQtl/src/wgpu_rhi_item.cpp`)
- `RenderEngine` を `RenderContext` 内に統合。
- Qt Quickの `WgpuRhiItem` から渡されるネイティブテクスチャ（Vulkan/Metal/DX12）に対して、NeoUtlの `RenderEngine` が描画結果を出力／合成。
- タイムライン再生時、指定フレームのアクティブオブジェクト・エフェクトがリアルタイムにゼロコピーで画面上にプレビュー描画されるようにする。

### 2.5 QML GUIの設計・実装 (`NeoQtl/qml/`)
eguiで提供されていたUI機能をモダンなQMLコンポーネントとして再設計：
- **`Main.qml`**: メインウィンドウ。Qt Quick Controls 2によるダークテーマ、レスポンシブなスプリットビュー構成。
- **メニューバー**: ファイル（新規、開く、保存、別名保存、エクスポート、終了）、編集（Undo/Redo）、表示、設定、ヘルプ。
- **プレビューパネル**: `WgpuRhiItem` 埋め込み、再生・一時停止、前後フレーム送り、シークスライダー、タイムコード・フレーム番号表示。
- **タイムラインパネル**: トラック一覧、レイヤー表示、クリップバー（ドラッグ移動・選択・トリミング対応）、ルーラー表示。
- **プロパティパネル**: 選択クリップのトランスフォーム（座標、拡大縮小、回転、不透明度）、オブジェクト固有属性、付加エフェクト一覧と各パラメータ調整スライダー/入力。
- **ダイアログ群**:
  - プロジェクト設定 / シーン設定ダイアログ（解像度、FPS、総フレーム等）
  - エフェクト追加ダイアログ（カテゴリ別カタログからの選択）
  - エクスポートダイアログ（出力ファイル、解像度、エンコード進捗表示）
  - システム設定ダイアログ（スレッド数、オーディオ等）

### 2.6 Rust <-> QMLブリッジ (`NeoQtl/src/ffi.rs`, `NeoQtl/src/bridge.rs`)
- QMLからのユーザーアクション（再生/停止、シーク、クリップ操作、値変更、保存/読込、エクスポート）を受け取り、Rust側のECS・プロジェクトセッションを操作。
- Rust側からの通知（現在フレーム更新、プロジェクト状態変更、レンダリングトリガー）をQML側に通知。

## 3. 実装ステップと作業手順

1. **ステップ 1: 依存関係とリソースの整備**
   - `NeoQtl/Cargo.toml` の依存関係を拡張。
   - `i18n/`, `assets/` などの共通アセットを `NeoQtl/` に複製。
2. **ステップ 2: ロジックコードの移植**
   - `src/` の非UIモジュールを `NeoQtl/src/` にコピー。
   - `egui_wgpu::wgpu` 参照を `wgpu` に置換し、egui依存を除去。
3. **ステップ 3: QML AOTコンパイル＆ビルドフロー構築**
   - `NeoQtl/build.rs` を改修し、`qmlcachegen` によるAOTコンパイル、ローダー生成、フィルタリングRCCを実装。
   - `neoutl_object_shader_build` によるSlangシェーダーコンパイルを組み込む。
4. **ステップ 4: レンダリングエンジンとQML WgpuRhiItemの結合**
   - `renderer.rs` に `RenderEngine` を組み込み、ECSのアクティブオブジェクト描画をRHIテクスチャに反映。
5. **ステップ 5: QMLコンポーネント群の実装**
   - メインウィンドウ、プレビュー、タイムライン、プロパティ、各種ダイアログのQMLを作成。
6. **ステップ 6: FFI / ブリッジの実装**
   - QMLとRustの相互作用を接続（再生ループ、シーク、パラメータ更新、コマンドディスパッチ）。
7. **ステップ 7: ビルド検証とテスト**
   - `cargo build -p NeoQtl` がエラーなく通ること、QMLファイルなしでもバイナリが自己完結して起動することを確認。
